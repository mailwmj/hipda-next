## 二、核心设计与 R-D7 S1–S4 收口说明

### 2.1 免打扰纯函数（`QuietHoursChecker.kt`）
- `isInQuietHours(currentMinutesOfDay, silentModeEnabled, beginMinutes, endMinutes)`：
  - `silentModeEnabled == false` 恒返回 `false`；
  - 所有分钟数经 `Math.floorMod(..., 1440)` 归一至 `[0, 1439]`；
  - `begin == end` 视为无免打扰窗口返回 `false`，避免误全天静音；
  - 同日区间（`begin < end`）：左闭右开 `current in begin until end`；
  - 跨午夜区间（`begin > end`，如默认 `22:00–08:00`）：`current >= begin || current < end`（`22:00`/`23:59`/`00:00`/`07:59` 命中，`08:00`/`21:59` 不命中）。

### 2.2 提醒轮询 Worker 与系统通知发布（`NotificationPollingWorker.kt`、`NotificationPoster.kt`）
- **4 级零网络前置门禁**（任一命中立即返回 `Result.success()` 且发起 **0 次网络请求**）：
  1. 应用前台可见（`AppVisibilityProvider` 默认读取 `HiApplication.isAppVisible()`）；
  2. `settingsRepository.settings.first().notificationsEnabled == false`；
  3. `QuietHoursChecker.isInQuietHours(...) == true`（经可注入 `PollingClock` 默认读取本地 `LocalTime.now()`）；
  4. 未登录或已手动退出（`hasActiveAccount()`：先读 `authRepository.currentAccount.value != null`；若为 `null` 则检查 `credentialsStore` 排除手动退出/无激活账号，并在冷启动后台进程唤醒场景下有限等待 `DefaultAuthRepository` 完成首次凭据水合，避免冷启动误跳过）。
- **静默轮询与杜绝重试风暴**：
  - 显式调用 `notifyRepository.pollUnreadCounts(priority = AccessPriority.BackgroundSilent)`；
  - `NotificationPollResult.Success`：有未读时二次复核应用仍不可见且仍登录，调用 `notificationPoster.postUnread(snapshot)`；双计数为 `0` 时调用 `notificationPoster.cancel()`；
  - `NotificationPollResult.ChallengeAbandoned` / `AuthRequired` / `Failed` 均安静返回 `Result.success()`，**绝不返回 `Result.retry()`**，杜绝 Cloudflare 验证触发后台重试风暴或弹窗；`CancellationException` 一律原样上抛不吞掉。
- **通知展示与术语统一（`AndroidNotificationPoster`）**：
  - 复用通知渠道 `HIPDA_NOTI`（`"论坛通知"`）与通知 ID `0`，点击跳转 `IntentActivity`（携带 `Constants.INTENT_NOTIFICATION` 及对应 extras）；
  - `smsUnreadCount == 1 && notifyUnreadCount == 0 && latestUnreadSms != null` 按单条预览展示 `"<发送者> 的短消息"` 与摘要；
  - 其余汇总展示 `"HiPDA 论坛通知"` 与 `"您有 N 条新的短消息，M 条新的提醒"`（单侧仅显示非零项，全角中文标点，严格遵守 `product-design.md §8` 术语表，零禁止词组）；对 API 33+ 潜在 `SecurityException` 静默兜底。
