## 二、核心实现说明

1. **`PrePost` 预取与 R-B9b S3 Emoji 往返闭合（`DefaultPostRepository.kt`）**：
   - 经 `ForumHttpClient.getHtml(..., requireAuth = true)` 拉取 5 类 `PrePostRequest` 对应端点，提前检测 `memcp.php?action=bind` 跳转（通过自定义 `isPostResponseUnauthenticated` 豁免避免误触发静默重登）返回 `PrePostResult.RealNameBindRequired`；
   - 复用 `B9b` `PrePostParser.parse(html, mode)` 后，对返回给编辑器的 `subject` / `text` / `quoteText` 执行 `decodeNumericEntitiesForEditor`，同时还原双重转义 `&amp;#128512;` / `&amp;#x1F600;` 与单次数字实体 `&#128512;` / `&#x1F600;` 为真实 Unicode Emoji，且不误伤普通命名实体（`&amp;`、`&lt;`、`&gt;`）、BBCode 及非法码点（`<= 0`、代理区 `0xD800..0xDFFF`、`> 0x10FFFF`）；
   - 提交 `ReplyPost` / `QuotePost` 时亦对 `prePostInfo.quoteText` 执行解码归一化，确保即便上层直接传入未经 `fetchPrePost` 解码的原始 `PrePostInfo`，也会先还原真实字符再由 `ForumHttpClient.postGbkForm` 底层 `toGbkSafe` / `gbkFormBody` 统一重编码为 GBK + 十进制实体 `&#<cp>;`（如 `😀` → `%26%23128512%3B`、`𠮷` → `%26%23134071%3B`）。
2. **6 种写操作提交、正文处理、小尾巴与 30 秒冷却（`DefaultPostRepository.kt`）**：
   - 全写操作由 `submitMutex` 串行防止双击重复提交；
   - 30 秒冷却（`POST_COOLDOWN_MS = 30_000L`）使用可注入虚拟时钟 `nowMs`，剩余毫秒向上取整（`1..1000ms -> 1`，`<= 0ms -> 0`）；非编辑模式（含 `DeletePost`）冷却中立即返回 `CooldownActive(remainingSeconds)` 且 0 次网络请求；`EditPost` 不受冷却阻塞也不启动/刷新冷却；仅服务器确认成功才记录冷却，任何失败不锁冷却；账号切换/退出登录自动重置冷却（冷启动水合期间读取实时 `currentAccount.value?.uid`，消除切线程竞态）；
   - 未传 `PrePostInfo`（或缺 `formhash`）时自动预取最多 1 次，失败即返回明确结果不发盲 POST；
   - 正文按序自动附尾未插入正文的 `newAttachments`（`[attachimg]<id>[/attachimg]`，`DeletePost` 除外）、对非 BBCode 标签区间裸 URL 包装 `[url]...[/url]`（保留成对括号并剔除尾部外层标点）、仅非编辑/非删除且 `tailEnabled == true` 且 `tailText` 非空时拼接小尾巴（有 `tailUrl` 规范化补 `https://` 拼 `[url=...][size=1]...[/size][/url]`，否则拼 `[size=1]...[/size]`，末尾已含不重复拼；**编辑与删除绝不拼小尾巴**）；
   - 成功判定：删除首楼 302 跳转 `forumdisplay.php` 返回 `Success(tid, threadDeleted = true, redirectedPage = null)`；跳转 `viewthread.php` 或 `redirect.php` 且 `tid`/`ptid` 合法则复用 `B8` `ThreadDetailParser.parse` 解析落地页；否则提取 `div.alert_error` / `div.alert_info` 返回 `SiteError`；
   - 草稿一致性：委托既有 `DraftDao`（不改 `Draft.kt`），全空内容不写入；仅提交成功时在 `NonCancellable` 下删除对应 `draftKey` 草稿，任意失败均保留草稿完好。
3. **纯 Android 图片压缩器（`ImageCompressor.kt`）**：
   - 零第三方压缩库依赖，直接使用 `BitmapFactory`、`Matrix`、`androidx.core.graphics.scale` 与 `androidx.exifinterface.media.ExifInterface`；
   - 兼容 `ContentUri` / `LocalFile` / `Bytes` 输入与 GIF 魔数/尺寸兜底解析；超大 GIF 直接返回 `ImageUploadError.GifTooLarge` 不转静图；合规 GIF、或 `original`/超长图（`max/min >= 3.0`）且无需 EXIF 旋转、受支持 MIME 且 `<= maxUploadBytes` 时直传；
   - 需压缩时按 `inSampleSize` 2 的幂降采样（含 OOM 降级重试）+ `Matrix` 矫正全部 EXIF 方向（旋转/镜像）+ 最大边上限 `2560px` 渐进缩放与 JPEG 质量递减（`80 -> 40`）直至 `<= maxUploadBytes`；`finally` 中确保所有 `Bitmap.recycle()` 与未交接临时文件清理。
4. **Multipart 图片上传仓储（`DefaultImageUploadRepository.kt`）**：
   - 直接注入 `SiteAccessGateway`、`SettingsRepository`、`AuthRepository`、`ImageCompressor`（未改动 `ForumHttpClient.kt`）；
   - `channelFlow` + `Channel.UNLIMITED` 发射 `Compressing` → 基于 `CountingFileRequestBody`（`isOneShot() == false` 可重放）的真实字节递增 `Uploading(bytesWritten, totalBytes, fraction)`（单调不降、完结达 `1f`）→ 复用 `B9b` `UploadResponseParser.parse` 发射 `Succeeded` 或 `Failed`；
   - 挂载 `AuthCookieWriteGuard`，遇未登录响应触发单飞静默重登最多重试 1 次（且不误判 `DISCUZUPLOAD` 业务失败或已登录组受限错误）；多图并发独立临时文件互不阻塞，单图取消立即通过 `invokeOnCompletion` 中止写流并取消 OkHttp `Call`、`finally` 清理临时文件且绝不吞掉 `CancellationException`。
