## 二、核心设计与并发状态机说明

1. **遗留密码转义与 MD5（`PasswordMd5.kt`）**：
   - 空串抛 `IllegalArgumentException`（消息不含输入）；
   - 32 位 hex（`^[0-9a-fA-F]{32}$`）直接转小写返回；
   - 否则严格按 `LoginHelper.java:175-177` 顺序先 `\` → `\\` 再 `"` → `\"`（单引号按 Java 字面量 `"\'"` 语义不加反斜杠），对 UTF-8 字节取 32 位小写 hex MD5；在 `PasswordMd5Test` 中通过反射与真实 `LoginHelper.processedPassword()` 逐例对照锁定字节等价。
2. **Cookie 精准清理（保留 `cf_clearance` / `__cf_bm`）**：
   - 不改 `SiteCookieStore` 接口：若当前论坛主机无 Cloudflare Cookie 则调用 `clearForHost(host)`；若存在 `cf_clearance` / `__cf_bm`，则仅将匹配当前主机的非 CF 会话 Cookie（保留各自 `name`、`domain`、`hostOnly`、`path`、`secure`、`httpOnly`）以 `expiresAt(0L)` 覆写删除，完整保留 `cf_clearance` 与其他主机 Cookie。
3. **单飞静默重登与 `@RecoveryHttpClient` 隔离**：
   - `trySilentRelogin` 先读取最新持久化态并核对 `authGeneration`；`manuallyLoggedOut == true` 返回 `Suppressed`（0 网络请求），无激活账号返回 `NotLoggedIn`（0 网络请求）；
   - 若 `failedEpoch < sessionEpoch` 直接返回 `Recovered(sessionEpoch)`（0 网络请求）；
   - `INVALID_CREDENTIALS` 失败记录 `(uid, passwordMd5)` 抑制重复撞库（防 Discuz! 15 分钟锁定），直至显式 `login`/`switchAccount`/`logout`/`removeAccount` 清除；
   - 并发请求通过 `stateLock` + `ActiveRelogin`（`CompletableDeferred` + 独立 `scope` 协程）合流为至多 1 次登录；单个等待者（含首个发起者）取消仅取消其自身 `await()`，不中断在途重登；`runSilentRelogin` 用 `finally { completeSilentRelogin(...) }` 防止任何异常导致永挂；
   - 静默重登请求走基于 `@RecoveryHttpClient OkHttpClient` 构造的独立恢复 `SiteAccessGateway`，运行在 `"OkHttp Recovery Dispatcher-*"` 线程池，即使主 `OkHttpClient` 的 Dispatcher 完全饱和仍可无死锁完成；`BackgroundSilent` 在主/恢复网关非 `Idle` 或遇 Cloudflare 403/429/503 时立即放弃返回 `Failed(CHALLENGE_ABANDONED)`（0 次调 `ChallengeSolver`）；
   - `logout` / `login` / `switchAccount` / `removeAccount(active)` 通过 `operationMutex` 串行，递增 `authGeneration`、作废并 `cancelAndJoin` 在途静默重登后再清 Cookie；`init` 对 `CredentialsStore` 流的订阅使用 `.conflate()` 触发 + 按 `authGeneration` 校验从存储现读最新快照，消除滞后旧帧倒流覆盖新状态竞态（首次 CI `45611912906` 暴露并已在 `df1c12d` 彻底修复）。
4. **`ForumHttpClient` 统一执行器**：
   - 每次请求动态读取 `SettingsRepository.settings.first().forumServer` 拼装 `{forumServer}/forum/{relativePath}`；
   - 经 `SiteAccessGateway` 执行，`decodeBody` 解码并 `DiscuzCommonParser.parsePageMeta` 解析；非 2xx 抛 `ForumHttpException`（不误触发重登）；
   - `requireAuth == true` 且 `!meta.session.isLoggedIn` 时，以请求前记录的 `sessionEpoch` 调 `trySilentRelogin`，仅在 `Recovered` 后使用全新 `Request` / 可重放 `gbkFormBody` 重试最多 1 次；重试仍未登录或重登未成功即抛 `AuthRequiredException`，绝不死循环。
