## 2. 七项改动明细与关键设计决策

### a. V-E16：工具条「在浏览器中打开」复用 `AndroidExternalLinkOpener`
- `PostLinkDispatcher.kt:118`：将 `DefaultPostLinkDispatcher.externalLinkOpener` 改为 `internal val`，复用现有 `LocalPostLinkDispatcher` 注入通路，不新建第二套 opener 或新 `CompositionLocal`。
- `ThreadBottomToolbar.kt:113-121`：`openExternalHttpUrl` 删除自建 `Intent(ACTION_VIEW, Uri.parse(...))`，继续先走 `sanitizeExternalHttpUrl(rawUrl)`（即 `SafeLinkPolicy.sanitizeHttpUrl`，拒绝 `mailto:` 及全部危险 scheme 与 `rawUserInfo`），随后委托 `(externalLinkOpener ?: AndroidExternalLinkOpener(context, startIntent)).open(safeUrl)`，自动继承排除本应用包名防 Intent 自环与无浏览器兜底逻辑。
- `ThreadDetailPane.kt:697,960-965`：通过 `(LocalPostLinkDispatcher.current as? DefaultPostLinkDispatcher)?.externalLinkOpener` 拿到宿主同一实例传入 `openExternalHttpUrl`；无可用外部浏览器返回 `false` 时，沿用现有 `R.string.routing_error_no_browser` 在 `DetailPane` 展示提示。

### b. R-M7-G3 S1：同帖重复点击同一链接 / 重复长按「直达末页」
- **方案选择：递增序号 `navSeq`（而非消费后复位）**
  1. **严格单向数据流，无反向通道**：消费复位需要 `ThreadDetailPane` 经 `MultiPaneReadingContainer` 回传回调到 `NextAppHostViewModel` 清除 `targetPid`/`openLastPage`，既增加跨层参数通道，又会在每次跳楼后触发一次额外的 `NextAppState` 状态写回与重组。`navSeq: Long = 0L` 在单一提交入口 `NextAppHostViewModel.commitOpenThread`（L330）自增盖章，单向传递至 `ThreadDetailPane` `LaunchedEffect(..., args.navSeq)`（L476）与 `ThreadDetailViewModel.bindArgs`（L316–358）。
  2. **天然保持旋转幂等与无竞态**：屏幕旋转（配置变更）时 `NextAppHostViewModel` 与 `ThreadDetailViewModel` 均保活，`args.navSeq == boundNavSeq`，即使已按 `Back` 回到 1 楼再旋转也不会重放旧跳转；同时避免“前一次跳楼的异步复位回调误清空后一次新跳楼参数”的竞态窗口。
  3. **零 `NextAppStateSaver` 兼容破坏**：`navSeq` 为进程内事件代际号，不改变 `NextAppStateSaver` 20 元槽位契约；进程重建后恢复默认 `0L`，后续新提交从 `1L` 递增继续生效。

### c. R-M7-G3 S2：`FloorShareHelper.buildSafeFloorShareUrl` 非回环一律输出 `https://`
- `FloorShareHelper.kt:24-28`：在 `buildSafeForumEndpointUrl` 中将 `preferHttps && parsed.scheme == "http" && !isLoopback` 的规范化条件去掉 `&& parsed.port == 80` 限制；仅在默认端口 `80` 时将端口转为 `443`（省略显式端口），非 `80` 端口（如 `http://example.com:8080`）保留端口号升级为 `https://example.com:8080`。回环地址（`localhost`、`127.0.0.1`、`::1`）与 `buildSafeWarningUrl`（`preferHttps = false`）行为不变。
