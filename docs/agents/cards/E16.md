【范围】

   - 定义不可变 `DeepLinkTarget` 与纯解析函数 `parseIncomingIntent(intent: Intent?, forumServer: String): DeepLinkTarget?`，并在 `NextAppHostViewModel` 新增 `applyDeepLink(target: DeepLinkTarget)`：

2. **帖子站内/站外链接统一分发器与严格 Scheme 白名单（`feature/routing/PostLinkDispatcher.kt`、`feature/common/LinkRoutingLocals.kt`、`PostBodyRenderer.kt`）**：
   - 在 `feature/common/LinkRoutingLocals.kt` 定义 `LocalPostLinkDispatcher` 与 `LocalAttachmentDownloadHandler`（默认 `null`，保持既有单测与未包裹宿主 100% 兼容）；
   - `NextAppRoot.kt` 提供真实分发器实现，`PostBodyRenderer.kt` 在未传显式 `onLinkClick` 覆盖时：
     - `ContentBlock.Text` / `ContentBlock.Quote` 内链接交由 `LocalPostLinkDispatcher`：
       1. **硬白名单前置守卫**：只允许 `http` / `https`（`HttpUrl` 合法且 host 非空、无首尾空白与 ISO 控制字符）及经过校验的纯邮箱 `mailto:`（无 query/header 注入）；
       2. 合法 `http`/`https` 先经 `ForumLinkResolver.resolve(safeUrl, forumServer)` 判断：命中站内链接（版块/帖子/楼层/用户）直接**应用内路由**（打开版块、帖子/跳楼、用户资料）；
       3. 非站内合法 `http`/`https` 或合规 `mailto:` 才安全交由系统浏览/邮件处理（`ACTION_VIEW` + `CATEGORY_BROWSABLE`，`runCatching` 兜底无浏览器异常）；
       4. 任何危险 scheme（`javascript:`、`intent:`、`file:`、`content:`、`data:`、`tel:`、`vbscript:`、`blob:`、`about:`、`market:`、`android.resource:`、大小写/前导空白/控制字符/空 host/畸形 `mailto:`）一律硬拦截，**0 导航、0 `startActivity`、0 `uriHandler.openUri`**。
3. **鉴权附件下载与安全保存（`feature/routing/AttachmentDownloader.kt`、`PostBodyRenderer.kt`）**：
   - `PostBodyRenderer.kt` 的 `ContentBlock.Attachment` 点击优先交由 `LocalAttachmentDownloadHandler`（不走裸系统 `DownloadManager`，避免缺 `SiteCookieStore`/`cf_clearance` 拿 403）；
   - **严格 `http`/`https` 白名单**：附件下载器只接受含非空 host 的 `http`/`https` URL（比正文更严：**拒绝 `mailto:`** 以及全部危险 scheme，拦截时 0 网络请求）；
