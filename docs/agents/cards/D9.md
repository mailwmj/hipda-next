【目标】实现基于 `WorkManager` + `HiltWorker` 的 15 分钟周期提醒轮询（严格遵循开关、跨午夜/同日免打扰、登录门禁与 `BackgroundSilent` 遇验证静默放弃），完成 `HiNextApplication` + `AndroidManifest.xml` 自定义 WorkManager 初始化并保证旧 `NotiWorker` 共存，同时闭合 `R-D7` S1–S4，通过离线单测与一次 API 36 Release 模拟器冷启动冒烟（本卡完成后 M3 全部收官）。

【范围】
1. **免打扰时段纯函数（`service/QuietHoursChecker.kt`）**：
   - `isInQuietHours(currentMinutesOfDay: Int, silentModeEnabled: Boolean, beginMinutes: Int, endMinutes: Int): Boolean`：
     - `silentModeEnabled == false` 恒返回 `false`；
     - `beginMinutes == endMinutes` 视为无免打扰窗口（返回 `false`，避免误全天静音）；
     - 同日区间（`begin < end`，如 `13:00–14:30`）：`current in begin until end`（左闭右开 `[begin, end)`）；
     - 跨午夜区间（`begin > end`，如默认 `22:00–08:00`）：`current >= begin || current < end`（`22:00`/`23:59`/`00:00`/`07:59` 为免打扰，`08:00`/`21:59` 非免打扰）。
2. **`HiltWorker` 提醒轮询 Worker 与系统通知发布器（`service/{NotificationPollingWorker,NotificationPoster}.kt`）**：
   - `@HiltWorker class NotificationPollingWorker @AssistedInject constructor(@Assisted appContext: Context, @Assisted params: WorkerParameters, ...)` 继承 `CoroutineWorker`；
   - **前置 4 级零网络门禁**（任一命中即直接返回 `ListenableWorker.Result.success()` 且发起 **0 次网络请求**）：
     1. 应用正在前台可见（通过可注入 `AppVisibilityProvider` 默认读取 `HiApplication.isAppVisible()`，方便单测控制）；
     2. `settings.notificationsEnabled == false`；
     3. `QuietHoursChecker.isInQuietHours(currentMinutesOfDay, settings.silentModeEnabled, settings.silentBeginMinutes, settings.silentEndMinutes) == true`（当前时间通过可注入时钟提供）；
     4. `authRepository.currentAccount.value == null`（未登录或已手动退出）。
   - **后台静默轮询与绝不重试风暴**：
     - 显式调用 `notifyRepository.pollUnreadCounts(priority = AccessPriority.BackgroundSilent)`；
     - `NotificationPollResult.Success`：有新未读（`smsUnreadCount > 0 || notifyUnreadCount > 0`）则通过 `NotificationPoster` 发布系统通知（复用渠道 `HIPDA_NOTI`；`smsUnreadCount == 1 && notifyUnreadCount == 0` 且带 `latestUnreadSms` 时按旧版单条预览文案展示发送者与摘要；否则汇总显示短消息与提醒条数，遵守 `product-design.md §8` 术语“短消息 / 提醒”）；双计数均为 `0` 时按需取消旧通知；返回 `Result.success()`；
     - **`NotificationPollResult.ChallengeAbandoned` → 立即安静返回 `Result.success()`（严禁返回 `Result.retry()`！杜绝 Cloudflare 验证触发后台重试风暴、杜绝弹验证面板）**；
     - `NotificationPollResult.AuthRequired` / `NetworkError` / `SiteError` → 安静返回 `Result.success()`（等待下个 15 分钟周期自然重试，不触发 WorkManager 退避重试风暴）；绝不吞掉 `CancellationException`。
3. **周期调度器与 Hilt 绑定（`service/NotificationScheduler.kt`、`di/NotificationWorkModule.kt`）**：
   - 使用独立唯一任务名（如 `WORK_NAME = "hipda_next_notification_polling"`，不与旧 `NotiWorker` 的 `"noti_work"` 冲突）；
   - `PeriodicWorkRequest` 周期 **15 分钟**，约束 `NetworkType.CONNECTED`；
   - 提供 `syncSchedule(notificationsEnabled: Boolean)`、`schedule()`（`ExistingPeriodicWorkPolicy.KEEP` 避免重复重置计时器）与 `cancel()`（`cancelUniqueWork`），以及供后续 `E12` 设置开关和启动流程复用的接口。
4. **`HiNextApplication.kt` 与 `AndroidManifest.xml` 自定义 WorkManager 初始化（共享文件显式授权）**：
   - `HiNextApplication` 实现 `androidx.work.Configuration.Provider`，注入 `@Inject lateinit var workerFactory: HiltWorkerFactory`，覆写 `override val workManagerConfiguration: Configuration` 返回带 `setWorkerFactory(workerFactory)` 的配置；保留继承自 `HiApplication` 的全部旧初始化逻辑；
