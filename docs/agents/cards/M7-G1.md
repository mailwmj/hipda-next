   - **旧版位置**：`hipda/src/main/java/net/jejer/hipda/ui/UserinfoFragment.java:119-130`。
   - **旧版行为**：点击用户资料页大头像时，若头像 URL 非空则清除该 URL 缓存、立即重新加载头像并提示 `头像已经刷新`；若为空则不发请求并提示 `用户未设置头像`。
   - **新版落点**：`feature/profile/UserProfileScreen.kt:133-144`（`ProfileFixedHeader`）、`res/values/strings_settings_profile.xml`（或 `strings_profile.xml`，按现有资料页字符串文件归口）。
   - **期望行为**：为 `64dp` 大头像添加显式稳定的 Coil `memoryCacheKey(safeAvatar)` 与 `diskCacheKey(safeAvatar)`，并绑定 `.clickable`（`Role.Button`）；点击时：
     - 若 `safeAvatar != null`：清除 Coil 内存中所有匹配该 `safeAvatar` 的缓存键（覆盖带尺寸 extras 的 `MemoryCache.Key`），在 `Dispatchers.IO` 调用 `imageLoader.diskCache?.remove(safeAvatar)` 精确失效磁盘缓存，随后递增重载 nonce（首次刷新请求绕过旧缓存重新拉取）触发重新加载，并经 `LocalPaneSnackbarController` 提示 `头像已经刷新`（逐字取自 `UserinfoFragment.java:125`）；
     - 若 `safeAvatar == null`：不触发缓存清除、不发请求，经 `LocalPaneSnackbarController` 提示 `用户未设置头像`（逐字取自 `UserinfoFragment.java:127`）。
   - **撤回即红测试**：在 `UserProfileScreen` 单元测试中预置自定义 `ImageLoader`（含内存 + 磁盘缓存哨兵条目与请求计数），(a) 有头像时点大头像验证内存与磁盘对应 key 均被移除、触发一次新头像请求且弹出 `头像已经刷新`；(b) 无头像时点大头像验证缓存未被误清、0 新请求且弹出 `用户未设置头像`；撤回缓存失效或点击回调测试立即变红。
