【范围】
1. **领域模型（`data/message/MessageModels.kt`）**：
   - 定义不可变模型（复用 `B9a` `SmsConversationItem`/`SmsMessageItem`/`NotifyItem`/`PromptCounts`）：
     - `SmsSendOutcome`（如 `Sent`、`CooldownActive(remainingSeconds: Int)`、`FormhashMissing`、`Rejected(message: String)`、`AuthRequired`、`Error(message: String, cause: Throwable?)`）；
     - `NotifyEntry(val key: String, val item: NotifyItem, val isRead: Boolean)`（带跨刷新稳定的确定性 `key`）；
     - `UnreadSnapshot` / `NotificationPollResult`（面向 `D9` WorkManager 轮询：含 `smsUnreadCount`、`notifyUnreadCount`、单条未读短消息预览 `latestUnreadSms: SmsConversationItem?`，便于 `D9` 构建通知栏文案，且明确区分 `ChallengeAbandoned` / `AuthRequired` / `Failed`）。
2. **短消息仓储（`data/message/{SmsRepository,DefaultSmsRepository}.kt`）**：
   - `getConversations(unreadOnly: Boolean = false, priority: AccessPriority = AccessPriority.UserBlocking)`：经 `ForumHttpClient` GET `pm.php?filter=privatepm`（或 `newpm`），`requireAuth = true`，复用 `B9a` `SmsParser.parseSmsList`，并同步刷新未读短消息计数；
   - `getConversationDetail(uid: String, priority: AccessPriority = AccessPriority.UserBlocking)`：经 `ForumHttpClient` GET `pm.php?daterange=5&uid={uid}`，`requireAuth = true`，复用 `B9a` `SmsParser.parseSmsDetail`（按 `SettingsRepository` 推导 `avatarBaseUrl`）；打开对话成功加载后将对应会话未读状态同步更新；
   - `sendSms(uid: String?, username: String?, message: String)`:
     - **15 秒冷却**：内置可注入时钟（`nowMs: () -> Long`，单测可注入虚拟时钟零 `sleep`），冷却窗口 `15_000L` ms；对外提供 `cooldownUntilMs: StateFlow<Long>` / `getRemainingCooldownSeconds(): Int`（剩余毫秒按 `product-design.md §7.3` **向上取整**，如 `1ms–1000ms` → `1` 秒，`0ms` → `0` 秒）；
     - 并发防重入（`Mutex`）：冷却未结束时立即返回 `CooldownActive(remainingSeconds)`，**发起 0 次网络请求**；校验空消息与收件人（`uid`、`username` 不能同时为空）；
     - 第 1 步：经 `ForumHttpClient` GET `pm.php?daterange=1&uid=${uid.orEmpty()}`（`requireAuth = true`）提取 `formhash`（缺失直接返回 `FormhashMissing`，不发 POST）；
     - 第 2 步：经 `ForumHttpClient.postGbkForm` 提交 `pm.php?action=send&pmsubmit=yes&infloat=yes&inajax=1`（有 `uid` 附 `&uid={uid}`，无 `uid` 表单加 `msgto={username}`），字段为 `formhash`、`lastdaterange`、`handlekey="pmreply"`、`message`，**`requireAuth = false`**；交由 `B9a` `SmsParser.parseSmsSendResult` 解析；
     - **仅当 `SmsSendResult.Success` 时记录发送时间并开启 15 秒冷却**；服务端拒绝或网络失败时不启动冷却，方便 `E8` 原地重发。
   - `clearConversation(uid: String)`：经 `ForumHttpClient` GET `pm.php?action=del&uid={uid}&filter=privatepm`（`requireAuth = true`），检查 `meta.errorMessage` 与 HTTP 结果。
3. **提醒本地已读存储（`data/message/NotifyReadStateStore.kt`）**：
   - 基于独立非加密 Preferences DataStore（文件名 `notify_read_state`，即 `notify_read_state.preferences_pb`，通过 `MessageModule` 提供）持久化已读提醒键集合与全量已读水位/状态，按账号 `ownerUid` 隔离（切换账号或退出登录不串号）；
   - 配置 `ReplaceFileCorruptionHandler { emptyPreferences() }` 与读流 `IOException` 兜底；对已读键集合做合理上限裁剪（如保留最近 500 条）防长期无限膨胀。
4. **提醒与未读数仓储（`data/message/{NotifyRepository,DefaultNotifyRepository}.kt`）**：
   - **三栏契约核心 — 严格分离的两条未读数流**：
     - `smsUnreadCount: StateFlow<Int>`（独立，永不与提醒混加）
     - `notifyUnreadCount: StateFlow<Int>`（独立，反映当前未读提醒数）
     - 订阅 `AuthRepository.currentAccount`：退出登录（`null`）或切换账号时立即清零内存计数并切换该账号的已读态隔离空间。
   - **提醒列表加载与按条/全部已读（`product-design.md §7.1, §7.6`）**：
     - `getNotifications(priority: AccessPriority = AccessPriority.UserBlocking)`：经 `ForumHttpClient` GET `notice.php`（`requireAuth = true`），复用 `B9a` `NotifyParser.parseNotifyList`（处理真机空态 `notify_list.html` 不报错）；
     - 为每条 `NotifyItem` 生成确定性稳定 `key`（由 `kind`、`tid`、`pid`、`authorUid`、`time`、`title` 等稳定字段计算，同一条提醒反复刷新 `key` 一致），与 `NotifyReadStateStore` 合并得到 `List<NotifyEntry>`；**加载 `notice.php` 不会自动把未打开的条目全部标成已读**；
     - `markNotificationRead(key: String)`：仅将该条持久化标记已读，并更新对应条目状态与 `notifyUnreadCount`；
     - `markAllNotificationsRead()`：将当前已知全部提醒标记已读并持久化，将 `notifyUnreadCount` 置为 `0`。
   - **面向 `D9`（WorkManager 后台轮询）与页头同步的入口**：
     - `pollUnreadCounts(priority: AccessPriority = AccessPriority.UserBlocking): NotificationPollResult`：经 `ForumHttpClient` GET `pm.php?filter=newpm`（`requireAuth = true`，**原样透传 `priority`**），同时从同一响应解析：
       - 未读短消息列表（`SmsParser.parseSmsList` → 更新 `smsUnreadCount`，单条时带出预览 `SmsConversationItem`）
       - 页头提醒计数（`meta.promptCounts.notifyTotal` → 与本地未读提醒状态协调更新 `notifyUnreadCount`，不把未打开的本地未读误清零）
       - 当 `D9` 传入 `AccessPriority.BackgroundSilent` 且底层抛出 `ChallengeAbandonedException` 时，明确映射为放弃结果而不报错重试风暴、不触碰既有计数。
     - `updateFromPageMeta(promptCounts: PromptCounts)`：允许其他页面加载后将 `DiscuzPageMeta.promptCounts` 增量同步到未读流（不强制覆盖尚未打开的本地未读提醒）。
5. **独立 Hilt 绑定（`di/MessageModule.kt`）**：
   - 独立 `@Module @InstallIn(SingletonComponent::class)`，定义 `@NotifyReadStateDataStore` 限定符，创建 `notify_read_state` Preferences DataStore（含 `ReplaceFileCorruptionHandler`），绑定 `@Singleton SmsRepository` 与 `@Singleton NotifyRepository`；不触碰任何既有 DI Module。
