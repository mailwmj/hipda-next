【范围】
1. **密码转义与 MD5（`data/auth/PasswordMd5.kt`）**：
   - 纯函数 `computeLegacyPasswordMd5(rawOrMd5: String): String`：空串抛出 `IllegalArgumentException`；已是 32 位 hex 直接转小写返回；否则按旧 `LoginHelper.java:175-177` 精确转义规则（`\`→`\\`、`"`→`\"`，单引号不加反斜杠）后取 UTF-8 字节 32 位小写 hex MD5（对照旧 `LoginHelper` 写验证测试锁死字节等价）。
2. **认证状态与 `AuthRepository`（`data/auth/{AuthModels,AuthRepository,DefaultAuthRepository}.kt`）**：
   - 状态流（面向三栏左栏账号槽、`E12`、`E15`）：
     - `currentAccount: StateFlow<SavedAccount?>`
     - `savedAccounts: StateFlow<List<SavedAccount>>`
     - `authState: StateFlow<AuthState>`（如 `SignedOut`、`SignedIn(account)`、`Reauthenticating`、`SessionExpired(account)`）
   - 核心方法：
     - `login(username: String, passwordOrMd5: String, securityQuestionId: Int = SavedAccount.NO_SECURITY_QUESTION, securityAnswer: String = ""): LoginResult`：
       - 从 `SettingsRepository` 读取 `forumServer` 构建登录 URL；
       - 经 `SiteAccessGateway`（`AccessPriority.UserExplicit`）GET 登录页并用 B9a `LoginParser` 解析；
       - 若已返回 `Ready(formhash)`，用 `gbkFormBody` 提交 `m_formhash`、`referer`、`loginfield="username"`、`username`、`password`（MD5）、`questionid`、`answer`、`cookietime="2592000"`，用 `decodeBody` 解码并交 B9a `LoginParser` 判定；
       - 登录成功后确认 `uid` 与规范大小写 `username`（通过后续轻量 GET 或登录页/首页 `#umenu` 经 B9a `DiscuzCommonParser` 解析），持久化 `SavedAccount` 至 `CredentialsStore.upsert(...)` 并调用 `setActive(uid)`（自动清除 `manuallyLoggedOut` 标记）。
     - `switchAccount(uid: String): LoginResult`：
       - 从 `CredentialsStore` 查找目标 `SavedAccount`；先清理当前论坛主机的登录 Cookie（`cdb_*` 等会话 Cookie——**尽量保留 `cf_clearance`** 以免无谓重触发 Cloudflare 验证，实现上可通过只用过期 Cookie 覆写 `cdb_*` 或先快照再恢复 `cf_clearance`，不改 `SiteCookieStore` 接口）；
       - 使用目标账号的 `passwordMd5`、`securityQuestionId`、`securityAnswer` 执行登录；成功后 `setActive(uid)` 并更新 `lastLoginAt`；失败时不冒充已切入目标账号，状态清晰回落并返回失败原因。
     - `logout()`：
       - 调用 `credentialsStore.markManualLogout()`（保留已保存账号列表、置 `manuallyLoggedOut = true`、清空 `activeUid`），清理论坛登录 Cookie（保留 `cf_clearance`），取消/失效当前静默重登世代，**此后绝不自动静默重登**，直到用户显式 `login` 或 `switchAccount`。
     - `removeAccount(uid: String)`：若为当前激活账号先清理登录 Cookie 再调用 `credentialsStore.remove(uid)`；否则仅删除保存凭据。
     - `trySilentRelogin(failedEpoch: Long, priority: AccessPriority = AccessPriority.UserBlocking): SilentReloginResult`：
       - **严格门禁**：`manuallyLoggedOut == true` 或无激活 `SavedAccount` 时立即返回 `Suppressed`/`NotLoggedIn`，**发起 0 次网络请求**；
       - **独立恢复通道**：静默重登的 HTTP 请求必须走 `@RecoveryHttpClient OkHttpClient`（独立 `Dispatcher` 线程池，不占主 `OkHttpClient` 连接池，避免重入死锁）；遇到 Cloudflare 验证页时：`BackgroundSilent` 立即放弃返回失败（不排队、不弹窗），前台请求按网关语义处理且不死锁；
       - **单飞合流与世代号**：多协程并发调用时通过互斥锁 + `CompletableDeferred` + `sessionEpoch` 合流为**至多一次**在途静默重登（若 `failedEpoch < currentSessionEpoch` 说明刚重登成功，直接返回 `Recovered(currentSessionEpoch)` 不重复登录）；单个等待者协程取消**只取消自己**，不打断在途重登和其他等待者；
       - **防循环冷却/失败语义**：静默重登失败（密码变更/网络错误/验证未过）时将状态更新为 `SessionExpired` 并返回失败结果，上层不再二次重登。
3. **统一已鉴权网络执行器 `ForumHttpClient`（`data/auth/ForumHttpClient.kt`）**：
   - 供 `D4`–`D8b` 与 `D9` 复用的薄封装（通过构造注入 `SiteAccessGateway`、`SettingsRepository`、`AuthRepository`）：
     - `getHtml(relativePath: String, priority: AccessPriority = AccessPriority.UserBlocking, requireAuth: Boolean = false): ForumHtmlResponse`
     - `postGbkForm(relativePath: String, fields: List<Pair<String, String>>, priority: AccessPriority = AccessPriority.UserBlocking, requireAuth: Boolean = true): ForumHtmlResponse`
     - 自动从 `SettingsRepository` 读取 `forumServer` 拼装 `{forumServer}/forum/{relativePath}`，自动用 `decodeBody` 解码并解析 `DiscuzPageMeta`（复用 B9a `DiscuzCommonParser`）；
     - 当 `requireAuth == true` 且响应未登录（`!meta.session.isLoggedIn`）时，记录请求前 `sessionEpoch` 并调用 `authRepository.trySilentRelogin(epoch, priority)`：**仅在成功恢复后重试原请求最多 1 次**（使用全新 `Request` / 可重放 `RequestBody`）；若仍未登录或重登未成功，抛出/返回明确 `AuthRequiredException`（绝不死循环）。
4. **Hilt 绑定（`di/AuthModule.kt`）**：
   - 独立 `@Module @InstallIn(SingletonComponent::class)`，将 `DefaultAuthRepository` 绑定为 `@Singleton AuthRepository`，并提供 `ForumHttpClient`（不修改 `HttpClientModule.kt` 或任何其他已有 Module）。
