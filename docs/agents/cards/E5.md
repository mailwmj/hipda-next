【范围】
1. **毛玻璃拓扑与多栏约束（`feature/compose/QuickReplySheet.kt`）**：
   - 复用 `C4d` 的 `HiGlassStyle.Sheet`、`20dp` 顶部圆角、整体记 **1 个 `HiGlassMarker`**，严格复用帖子详情的 `detailGlassState`（与楼层 `LazyColumn` 严格兄弟节点，绝不新增第 3 个采样源）；
   - 面板挂载于 `ThreadDetailPane` 内部最顶层容器：**单栏全宽；三栏与物理铰链双栏仅在右栏宽度内升起，暗罩（scrim）仅盖右栏，绝不遮挡左栏与中栏**；
   - **同屏 ≤ 3 玻璃预算铁律**：快速回复面板展开期间，向 `ThreadBottomToolbar` 传递 `suppressBottomGlass = true`（彻底停绘并卸载底部工具条的 `drawBackdrop` 与 `HiGlassMarker`），确保三栏下保持 `HiGlassMarker ≤ 3`、独立 `LayerBackdrop ≤ 2`、静止 `drawBackdrop ≤ 5`；关闭面板后自动恢复底部工具条；若上方全屏看图（`LocalHiGlassSuspended == true`）盖住，同步遵守暂停采样。
2. **动态限高、IME 逐帧升降与矮屏紧凑态（§7.3）**：
   - 通过 `WindowInsetsAnimation` / `imePadding()` 逐帧随键盘升降并自动聚焦输入框；
   - 面板最大高度动态钳制为 **`min(300.dp, 可视净高 × 60%)`**（可视净高扣除状态栏与 IME，输入框超出后内部纵向滚动，最低保底 1–2 行）；
   - **常规窗口**（窗口高 `≥ 480dp` 且键盘上方可视净高 `≥ 180dp`）：底层帖子列表按需上移/预留底部间距使正在读或被引用的目标楼层可见；
   - **矮屏/横屏弹键盘**（可视净高 `< 180dp`）：自动隐藏顶部 `32dp` 拖动把手与草稿恢复横条，压成紧凑输入行，优先保障输入框与 `发送` 按钮完整不溢出截断；净高 `< 120dp` 时用户仍可点 `展开全屏`。
3. **跟手拖拽、手势隔离与非手势关闭路径（§6.3、§7.3）**：
   - 顶部为 `32dp` 拖动把手（无障碍描述 `收起回复面板`）+ 回复/引用上下文提示（`回复 {用户名}` 或 `引用第 {N} 楼 · {用户名}`）+ 右上角 `48×48dp` **`展开全屏`** 按钮；
   - **垂直拖拽隔离**：下拉关闭与上拉展开全屏**仅由顶部 `32dp` 把手/标题区直接触发，或输入框滚动至顶边界且无文本选区态时经 `NestedScroll` 超界传递**；输入框内部优先响应多行纵向滚动与光标/选区拖拽，绝不抢占文本操作；松手按位置/速度以 `HiMotion.spatialSnap()` 弹回、`exit(...)` 关闭或 `spatialDefault()` 展开全屏；减动效 0ms 到位；
   - **非手势关闭路径**：点击右栏暗罩、系统返回键、把手上无障碍关闭动作均与下拉关闭走同一出口，保证无障碍完备；
   - **返回优先级**：面板打开时其 `BackHandler` 位于 `PositionStack` 与 `E3` 多栏返回栈之前（但低于 `NextAppRoot` 顶层 `ImageViewer`/`LoginOverlay` 与 `HiAdaptiveShell` 模态侧栏抽屉）；按返回先静默保存草稿并收起面板，不误出位置栈、不误关帖子。
4. **工具条布局、30 秒冷却、提交与 `E6`/`E7` 零返工交接（`feature/compose/QuickReplyViewModel.kt`、`ComposeContracts.kt`）**：
   - 底部工具行**仅保留与旧版 HiPDA 一致的 `插入图片`、`表情`（`≥ 48dp` 触控区，严禁加 `引用`/`粗体` 按钮，且本面板不内嵌多图上传缩略图条）+ 右侧固定 `发送` 按钮**；
   - **冷却倒计时（§7.3）**：订阅 `PostRepository.cooldownUntilMs`，30 秒冷却中 `发送` 按钮原地显示剩余秒数（向上取整，`HiRollingNumber`，无障碍 `{N} 秒后可发送`）且禁用防重发，倒计时期间允许继续编辑输入，归零自动恢复；
   - **发送与结果联动（§7.3）**：未登录原地显示 `登录后即可操作`（按钮 `登录`）；点 `发送` 0ms 按钮内切 `HiLoadingSpinner`（`正在发送…`）且留在本面板；失败留在面板原地提示原因保留全部输入供修改重试；成功删除 `reply:<tid>` 草稿——若用户本来就在末页末尾附近则刷新/插入新楼并平滑滚过去同时收起面板；否则收起面板**不移动阅读位置**并经 `LocalPaneSnackbarController(DetailPane)` 弹 `回复已发送`（按钮 `查看`，点击先压 `PositionStack` 再跳到新楼层）；**只看楼主/只看此人过滤模式下也可正常回复和引用**；
   - **`E6`/`E7` 交接契约（`ComposeContracts.kt`）**：定义 `@Immutable data class FullEditorHandoff(tid, fid, text, selectionStart, selectionEnd, quotePid, quoteAuthor, quoteFloor, openImagePickerImmediately)` 及可选回调/插槽——点右上角 `展开全屏`（或把手上拉越阈值）携当前文本、光标选区与引用楼层触发 `onExpandToFullEditor(handoff.copy(openImagePickerImmediately = false))`（**不重复触发草稿保存提示**）；点 `插入图片` 携同上参数触发 `onExpandToFullEditor(handoff.copy(openImagePickerImmediately = true))`；点 `表情` 预留 `emojiPanelSlot`（`E7` 接入前安全占位/回调不崩溃）。
5. **草稿自动保存、恢复与收口 `R-D6 S2`（§7.2）**：
   - 业务键统一为 `DraftKey.reply(tid)`；任何关闭途径（下拉/点暗罩/系统返回）若内容非空且与上次已发不同，静默调 `saveDraft` 并经 `LocalPaneSnackbarController(DetailPane)` 弹 `已保存草稿`（按钮 `放弃`，点击调 `deleteDraft`）；内容为空且从未恢复草稿时不保存不提示；
   - 再次打开同 `tid` 面板自动恢复草稿并在输入框上方显示横条 `已恢复上次草稿`（按钮 `清空`）；
   - **必修收口 `R-D6 S2`**：若用户恢复了一份已有草稿（`hadPersistedDraft == true`），随后手动删空全部文字或点 `清空` 后退出面板，**必须显式调用 `postRepository.deleteDraft(DraftKey.reply(tid))`**，杜绝旧草稿在下次打开时复活（并补撤回即红单测）。
   - **关于 `R-D6 S1`（记录备查）**：本面板不内嵌多图上传（`插入图片` 交由 `E6` 完整编辑器执行上传），`ImageUploadInput.original = false` 压缩默认由 `E6` 落实（如负责人派发前额外授权改 `data/post/PostModels.kt` 默认值则以派发附注为准，未授权前**不改 `data/post/*`**）。
