【任务卡 M7-3：targetSdk 升到 36——通知权限、MediaStore 下载与全面屏（高风险 R+V）】
分支：`card/M7-3-target-sdk-36`（基于含 `M7-2` 的 `origin/main` @ `c001dee`）
> **前置门禁与共享文件独占授权**：本卡**串行依赖 `M7-2`**（必须等旧 View 界面删除完毕后再升 `targetSdk`，按 `tech-plan.md` §4 T1 避免旧页面行为破坏）。本卡独占授权修改 `gradle/libs.versions.toml`（仅 `targetSdk = "36"`）与 `hipda/src/main/AndroidManifest.xml`；**严禁改动 `namespace`（`net.jejer.hipda`）、`applicationId`（`net.jejer.hipda.next`）、签名配置与 `.ng.IntentActivity` / `<queries>`**。

风险分级：**高风险（走 `R + V`）** — `targetSdk` 跨越 30 → 36（涉及 Android 13 通知权限、Android 10+ 分区存储/MediaStore 强约束、Android 15/16 强制全面屏 Edge-to-Edge、预测性返回与大屏自适应强规则；`V` 须含合入 `main` 后跨 API 28/36 矩阵探针）。
预计生产代码净增：约 150–300 行（1.5× 警戒 450 行）

【目标】
按 `docs/design/backlog.md` 第 92 行与 `docs/design/tech-plan.md` §4 将 `targetSdk` 由 `30` 升级至 **`36`**，完整闭环三类平台强制行为变更：API 33+ 运行时通知权限、API 29–36 无存储权限 `MediaStore` 下载/保存（兼容 API 26–28）、以及 Android 15/16 强制全面屏 Edge-to-Edge 与预测性返回适配。

- 规范：`docs/design/backlog.md`（M7-3）、`docs/design/tech-plan.md` §4（T1）/§8、`docs/design/product-design.md` §4.1/§6.3/§7.10、`docs/design/copy.md`

【范围】
1. **升级 `targetSdk` 至 `36`**：
   - 在 `gradle/libs.versions.toml` 将 `targetSdk = "30"` 改为 `targetSdk = "36"`（`hipda/build.gradle.kts` 与 `emoji/build.gradle.kts` 自动继承）；
   - 修复因 `targetSdk = 36` 引发的任何 Android Lint 高危错误与废弃 API 警告（例如导出/不可变 `PendingIntent`、`registerReceiver` 导出标志、移除过时 `android.max_aspect` 等）。
2. **通知权限（API 33+ `POST_NOTIFICATIONS`）**：
   - 在 `hipda/src/main/AndroidManifest.xml` 新增 `<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />`；
   - 在设置页开启 `接收提醒通知`（API 33+ 且尚未获授 `POST_NOTIFICATIONS`）时，通过 `ActivityResultContracts.RequestPermission` 请求运行时通知权限：
     - 授予后正常开启提醒轮询；
     - 拒绝（含永久拒绝）时不崩溃，原地展示明确提示并提供跳转系统通知设置入口（复用设置项 `通知声音与样式` / 系统应用通知设置页；文案严格对齐 `copy.md`，如需新增条目须先走规范并过 `CopyTerminologyScanTest`）；
   - 验证后台 `NotificationPollingWorker` 与 `AndroidNotificationPoster` 在通知权限被系统随时撤回时零崩溃（`SecurityException` 优雅吞并并保持状态一致）。
3. **`MediaStore` 下载与图片保存（分区存储合规）**：
   - 在 `hipda/src/main/AndroidManifest.xml` 为 `WRITE_EXTERNAL_STORAGE` 添加 **`android:maxSdkVersion="28"`**，严禁在 API 29+ 申请任何旧版外部存储权限或 `MANAGE_EXTERNAL_STORAGE`；
   - 核验并补齐测试：API 29–36 下帖子附件下载（`AttachmentMediaStoreSaver`）与看图保存相册（`ImageViewerMediaActions`）100% 走 `MediaStore.Downloads` / `MediaStore.Images`（`IS_PENDING = 1 -> 0`、异常清理）且 **0 次存储权限弹窗**；API 26–28 下仍走运行时 `WRITE_EXTERNAL_STORAGE` 申请与拒权零写入兜底；
   - 核验 `FileProvider` 分享图片与脱敏错误日志在 API 36 下 `FLAG_GRANT_READ_URI_PERMISSION` 正常工作。
4. **全面屏（Edge-to-Edge）、预测性返回与大屏合规**：
   - 正式主入口 Activity（及 `ChallengeActivity`）统一调用 `enableEdgeToEdge(...)`，并随 `HiTheme` 浅色 / 深色 / 纯黑 OLED 实时切换 `SystemBarStyle`（保证状态栏与导航栏图标在浅色与深色背景均具足够对比度，且无白条/黑条闪烁）；
   - 审查并验证全应用核心界面在**手势导航条**与**经典三键导航栏**、**顶部状态栏/刘海挖孔**以及 **IME 软键盘**下的 `WindowInsets` 处理：
     - 顶部内容自透明液态玻璃顶栏下方滚过且首项留足 `statusBars` 间距；
     - 底部导航胶囊、三段工具条、内联跳页条、毛玻璃快速回复面板、完整编辑器、表情面板、楼层菜单、看图工具栏与对话框均正确避让 `navigationBars` / `ime` 且**无双倍 padding**；
   - 在 `AndroidManifest.xml` 启用系统预测性返回 `android:enableOnBackInvokedCallback="true"`，验证全部 `BackHandler` 栈（看图 > 登录 > 抽屉 > 表情 > 快速回复/编辑器 > 位置栈 > 多栏返回栈）在 `targetSdk 36` 下正常工作且不破坏返回优先级；
   - 确认主入口及全部 Activity 无 `screenOrientation` / `resizeableActivity="false"` 锁定，完全符合 Android 16（`targetSdk 36`）大屏与折叠屏强制自适应要求；
   - 验证 `BackupExclusionRulesTest`（`data_extraction_rules.xml` 与 `backup_config.xml` 在 API 36 下仍严格排除 Tink 密钥与加密 DataStore）。

【验收标准】
