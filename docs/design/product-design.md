# hipda-next 产品设计方案（草案 v0.1）

> 状态：草案，待 Carbon 评审。依据：用户的设计要求（见 `docs/agents/decisions.md`）、R1 对 fluxdo 的调研（`/tmp/hipda-research/fluxdo-analysis.md`，F1 核查中）、对旧代码按状态变化做的审计。H1 的完整状态变化清单（106 条，其中 P0 42 条）见 `/tmp/hipda-ux/state-inventory.md`，定稿时随文档一起归档到 `docs/design/state-inventory.md`。待补充：R2 对其他折叠屏应用的调研。技术实现见 `tech-plan.md`。

## 1. 为谁、做什么
- 用户：HiPDA 的老用户。高频操作依次是：刷帖子列表、读长帖（翻页、跳楼层、看引用）、看图、快速回复、看短消息和提醒。
- 设备：单手用的手机；折叠屏合上时当手机用，展开后边看列表边读帖；平板；分屏时的窄窗口。
- 目标：读得舒服，找得快，回得顺手。所有复杂的事都由系统处理，用户只管看帖和回帖。

## 2. 设计原则（每条都对应第 10 节的验收）
1. **系统能判断的，不留给用户。** 编码、主题、图片加载策略、阅读位置、登录续期、Cloudflare 验证，都由系统自动处理。
2. **此刻没用的，就不出现。** 不显示数值为 0 的角标；页码只在滚动或需要跳页时出现；失效的功能直接删除。
3. **能替人做的，就直接做。** 草稿自动保存；发送失败时内容保留，可以原地重试；离开再回来，从上次读到的地方继续。
4. **同一件事，处处一样。** 一套术语、一套组件、一套动效语言。
5. **按下去有回应，再按能收回。** 按下立即有反馈；收藏、关注这类开关操作立即生效，可以撤销。
6. **不打断人手上的事。** 错误在出错的地方原地提示，不弹窗；新消息只用角标提醒；刷新时不把人拉回顶部。
7. **常用的好做，会丢东西的难误碰。** 回复入口在拇指够得到的位置；删帖、清除登录信息要确认或者能撤销；去掉双击就跳页这类容易误触的手势。
8. **界面自己说明自己。** 不加不必要的次级标签和说明文字；空状态和错误状态直接告诉用户下一步能做什么。

## 3. 信息架构
- 一级目的地共 4 个：**论坛**（版块和帖子列表）、**消息**（短消息和提醒合在一起）、**搜索**、**我的**（收藏、浏览历史、我的帖子、设置、账号）。旧版的抽屉菜单取消。
- 版块切换：在论坛页顶部放一行版块标签，只显示用户关注的版块，横向滑动。这一行随顶栏一起，向下滚动时收起，向上滚动时露出。“管理版块”放在这行的最后一项。
- 未读提醒：只在“消息”图标上显示角标，没有未读时不显示。
- 帖子详情、用户资料、看图、发帖都不是一级目的地，是从列表或帖子里进入的下一级页面。

## 4. 自适应布局
### 4.1 宽度分档与导航形态
| 窗口宽度 | 典型设备 | 导航形态 | 内容 |
|---|---|---|---|
| 小于 600dp | 手机、折叠屏外屏、分屏窄窗口 | 底部悬浮的毛玻璃胶囊导航，向下滚动时滑出屏幕，向上滚动时回来 | 单栏 |
| 600–839dp | 折叠屏内屏竖着拿（约 700dp，待核实）、小平板 | 底部胶囊导航，悬浮在左侧列表栏的下方居中，不占横向宽度 | 双栏：列表 300dp，详情占剩下的宽度（至少 380dp）。放不下时单栏 |
| 840dp 及以上 | 折叠屏内屏横着拿、平板 | 左侧毛玻璃导航轨，宽 80dp | 双栏：列表 360dp，往宽了长时最多占 40%；详情占剩下的宽度 |
| 高度小于 480dp（手机横屏） | — | 无论宽度多少，都用底部胶囊导航 | 按宽度决定 |

- 何时双栏由系统决定，没有开关。中等宽度下不使用 Material 默认的单栏策略，改用自定义的分栏规则（见 tech-plan）。这些数值在 M4 阶段，用截图测试在几种真实设备尺寸上校准，包括 Pixel Fold 和 Galaxy Z Fold 系列的内屏，竖着拿和横着拿都要看。
- 铰链：屏幕被铰链物理分开时（`isSeparating` 为真，例如半折的书本姿态），两栏的分界对齐铰链。内屏完全展平时，折痕不需要避让。半折、横放的桌面姿态（tabletop）不做特殊布局，按宽度正常显示。
- 帖子正文的最大行宽为 680dp（16sp 中文约 40 字一行），超出的部分居中留白。

### 4.2 每个页面在各宽度下的布局
| 页面 | 单栏 | 双栏 |
|---|---|---|
| 论坛 | 帖子列表 → 点击进入帖子详情 | 左：帖子列表；右：帖子详情。没选帖子时，右栏显示一个安静的占位（图标加一句话） |
| 消息 | 会话列表 → 对话 | 左：会话列表；右：对话 |
| 搜索 | 搜索框和结果 → 帖子详情 | 左：搜索框和结果；右：帖子详情 |
| 我的 | 菜单 → 子页面 | 左：菜单；右：子页面（收藏、历史、设置……） |
| 设置 | 分组列表 → 子页面 | 左：分组；右：子页面 |
| 帖子详情里点开用户资料 | 新页面 | 在右栏内进入下一级，左栏不变；返回时回到帖子原来的位置 |
| 发帖或回复 | 全屏编辑页；快速回复是底部输入条 | 在详情栏底部展开输入区；完整编辑器在详情栏内打开，宽度不超过 680dp |
| 看图 | 全屏 | 全屏 |

### 4.3 折叠、展开、旋转时的连续性
- 展开：如果当时正在看帖子，就变成双栏——帖子留在右栏，位置不变；左栏的列表自动滚到这条帖子，并高亮它。
- 折叠：如果双栏里右栏有帖子，就只留下帖子（单栏），返回时回到列表，列表停在原来的位置。
- 正在输入的回复、草稿、滚动位置、展开的引用，在任何形态变化后都保留。
- 布局切换的动画见 6.3 的“布局变化”。

## 5. 视觉
- **颜色**：Material 3 配色。Android 12 及以上默认从壁纸取色，只取一个主色作为种子，再按统一的规则生成整套颜色，保证同一套对比度；取不到时用 HiPDA 的品牌色作为种子。深色模式保留“纯黑”选项（OLED）。主题默认跟随系统。
- **字体与排版**：使用系统中文字体。帖子列表标题 16sp，行高 1.4；已读的帖子降一级字重并变灰。正文 16sp，行高 1.65。用户可以调字号，范围 −2 到 +4 级。
- **形状**：圆角统一分 4 档：小 8dp（标签、按钮）、中 12dp（卡片、楼层引用）、大 20dp（底部面板、对话框）、全圆角（胶囊导航、搜索框）。
- **层级**：不用阴影，靠表面颜色的深浅区分层级。只有悬浮在内容上面的东西（导航胶囊、底部面板）才带一层很淡的阴影。
- **毛玻璃**：只用在会叠在内容上面的导航和工具条上：底部导航胶囊、导航轨、帖子详情的底部工具条，以及滚动后的顶栏。
  - 参数（M4 阶段用截图校准）：模糊半径 24dp；着色为表面色，浅色模式透明度 70%，深色模式 60%；0.5dp 高光描边（浅色模式用白色 40%，深色模式用白色 12%）；悬浮胶囊下方加一层很淡的阴影。
  - 降级：Android 11 及以下、省电模式、系统开了“降低透明度”或高对比度时，改为不透明度 94% 的纯色表面加细描边。降级后文字对比度不低于 4.5:1。
  - 内容延伸到导航下面滚动；列表的末尾留出导航的高度，最后一条内容不会被挡住。
- **胶囊导航尺寸**：高 64dp；左右各留 16dp 边距，最宽 420dp，居中；距离手势条 8dp。选中项是一个浅色胶囊，切换时这个胶囊滑到新位置。

## 6. 动效系统
### 6.1 总则
- 动效是为了解释变化：东西从哪来、到哪去、和什么有关。不加装饰性的动效。
- 一套语言：所有动效只从 6.2 的令牌里取参数，代码里不能直接写时长和曲线。
- 克制：越常用的操作越快。切换一级目的地只做淡入淡出，不做位移。
- 跟手、可打断：凡是和位置有关的动画都用弹簧（spring），新的目标出现时从当前位置和速度接着走，不重新开始。拖动时，内容跟着手指走。
- 只动必要的属性：优先只动透明度、位移和缩放（graphicsLayer），不在动画过程中改变布局尺寸；必须改尺寸的（展开引用、布局切换），用 animateContentSize 或面板自带的动画，并检查滚动位置不跳。
- 减少动态效果：系统动画时长缩放为 0，或开了“移除动画”时，所有位移和缩放都改成 100ms 以内的淡入淡出，或者直接切换；数字直接变；不做视差效果。

### 6.2 令牌（基于 Material 3 MotionScheme.standard；数值在 M4 阶段用逐帧测试和真机校准）
| 令牌 | 用途 | 参数 |
|---|---|---|
| `spatialFast` | 小东西移动：选中胶囊、开关、图标位移 | 弹簧，阻尼比 0.9，刚度 1400 |
| `spatialDefault` | 页面和面板的移动、展开收起 | 弹簧，阻尼比 0.9，刚度 700 |
| `spatialSlow` | 大面积的布局变化：双栏出现或消失 | 弹簧，阻尼比 1.0，刚度 300 |
| `effectsFast` | 颜色、透明度的小变化，按压态 | 弹簧，阻尼比 1.0，刚度 3800 |
| `effectsDefault` | 内容替换时的淡入淡出 | 弹簧，阻尼比 1.0，刚度 1600 |
| `exitFactor` | 退场比入场快 | 退场用对应入场令牌，刚度乘以 1.5 |

不使用会明显回弹的曲线。只有在手指松开、带着速度甩出去的时候（关闭底部面板、拖动关闭看图），才允许轻微的过冲。

### 6.3 按状态变化分类的处理方式
| 变化类型 | 例子 | 处理方式 |
|---|---|---|
| 层级前进和后退 | 列表进入帖子；帖子进入用户资料 | 单栏：被点的列表项展开成详情页（容器变换），返回时缩回原来的列表项，列表的位置不变。双栏：右栏内容从右侧 24dp 处淡入，旧内容淡出。系统返回手势（预测性返回）跟手：页面随手指缩小、移动，松手后决定是完成返回还是弹回原位 |
| 出现和消失 | 底部面板、菜单、Snackbar、快速回复输入条、导航栏随滚动隐藏 | 从它的来源方向出现：菜单从按下的按钮处展开；面板从底部升起；Snackbar 从导航上方升起，同时把内容往上推。消失比出现快 |
| 内容替换 | 切换版块、刷新、翻页、切换“只看楼主” | 旧内容淡出、新内容淡入，同时新内容向上位移 8dp。刷新时保持当前的滚动位置；有新帖时在顶部出现“N 条新帖”的小胶囊，点一下滚到顶部 |
| 数值变化 | 未读数、回复数、页码、上传进度 | 数字逐位上下滚动：增加时向上，减少时向下。数字从 0 变成大于 0 时，角标从中心放大出现；变回 0 时缩小消失 |
| 图标变化 | 收藏和取消收藏；发送按钮变成对勾 | 旧图标缩小并淡出，新图标放大并淡入，两者同时进行。对勾用描线的方式画出来 |
| 按压 | 列表项、按钮、导航项 | 按下立即显示状态层，并缩小到 0.97；松开时弹回。不再有旧版那样的 200ms 延迟。确认类操作（收藏、发送成功、长按出菜单）配合一下轻微的触感反馈 |
| 加载、完成、出错 | 发送、上传、首次加载 | 都在原地变化：发送按钮变成进度圈，成功后变成对勾，再恢复成发送按钮；失败时变回发送按钮，输入框下方原地显示错误原因和“重试”。150ms 内完成的加载不显示加载指示，以免一闪而过。首次加载用和真实内容同样形状的骨架，内容到了以后原地淡入替换，不产生跳动 |
| 布局变化 | 折叠和展开、旋转、分屏改变宽度 | 两栏的宽度用 `spatialSlow` 过渡；正在阅读的内容保持在同一个阅读位置，不跳到别处 |
| 尺寸变化 | 展开长引用；图片加载完成 | 引用展开时，高度跟着内容一起变；图片在加载前就按真实宽高比占好位置，加载完淡入，不改变高度（服务器给了尺寸就用；没给的话先按 4:3 占位，加载完成后只调整这一项的高度，并保持阅读位置不动） |
| 拖拽 | 预测性返回、关闭底部面板、下拉关闭看图、看图时缩放 | 完全跟手；松手时按速度和位置决定结果，并带着这个速度进入动画 |

### 6.4 性能
- 帖子列表和长帖滚动时保持满帧。M5 阶段在 CI 的模拟器上用 Macrobenchmark 测量；用户有真机的话，也在真机上测一次。
- 列表项里不使用模糊；毛玻璃只用在导航和工具条上，全屏同时最多 2 块。
- 图片按显示尺寸解码，不解码原图。

## 7. 交互规范（结合对旧版的审计）
| 原则 | 旧版的问题（审计发现） | 新版的做法 |
|---|---|---|
| 系统能判断的 | 设置里有“使用 UTF8 编码”；图片按 Wi-Fi 和流量分别有三个设置项；主题要手动切换；重新打开帖子时总是从第 1 页开始 | 编码自动识别，删除这个设置；图片在 Wi-Fi 下自动加载，在流量下显示带尺寸的占位，点一下加载（只保留一个“流量下也自动加载图片”的开关）；主题默认跟随系统；帖子记住页码、楼层和偏移量，再打开时自动回到原处 |
| 此刻没用的 | 刷新按钮一直浮在屏幕上；抽屉里有显示“0”的角标；“检查更新”已经失效；页码标签一直显示 | 去掉刷新按钮，改成下拉刷新，并在内容过期后回到页面时自动刷新；数值为 0 的角标不显示；删除“检查更新”；页码只在滚动时出现在底部工具条里，点它可以跳页 |
| 能替人做的 | 退出编辑时弹“放弃发表？”；发送失败后内容只能去草稿里找；上传前图片不压缩 | 退出编辑时自动保存草稿，不再询问，下次打开同一个帖子的回复时自动恢复；发送失败时内容留在输入框里，原地可以重试；图片上传前自动压缩到合适的大小 |
| 同一件事处处一样 | “回复/回帖”“发表/发布”“只看楼主/只看该作者”等说法混用 | 统一术语（见第 8 节），并用测试检查（见第 10 节） |
| 按下去有回应 | 列表项按下后 200ms 才高亮；600ms 内的第二次点击被直接丢掉，没有任何提示 | 按下立即有反馈；用状态来防止重复提交，而不是靠时间丢弃点击 |
| 再按能收回 | 收藏、关注、投票的结果不能撤销 | 收藏和关注立即生效，Snackbar 里给“撤销”；投票提交前先选中选项，再点“投票”提交，这一步保持不变 |
| 不打断人手上的事 | 退出登录 1 秒后自动弹出登录框；错误用 Toast；切换主题时重启整个应用 | 退出登录后停在当前页，需要登录的地方原地显示“登录”按钮；错误在出错的位置原地提示；切换主题时颜色平滑过渡，不重启应用 |
| 难误碰 | 双击列表直接弹出跳页框；点其他账号的头像直接切换账号，没有确认；“退出并清除登录信息”和普通退出并排放着 | 去掉双击跳页；切换账号要先确认；清除登录信息放进账号管理的二级页面，并且需要确认 |
| 系统能判断的 | 置顶帖或黑名单过滤后，一页不足 10 条时，连续拉 5 页就停，然后弹 Toast 让用户去网页版改设置（ThreadListFragment.java:614-616） | 后台自动继续加载，直到能填满一屏；不再让用户去改网页设置 |
| 系统能判断的 | “只看该作者”模式下点回复，提示“请先退出只查看该作者模式”（ThreadDetailFragment.java:1071） | 在这个模式下也能直接回复和引用 |
| 系统能判断的 | 登录过期后整屏显示“未登录”，即使本地保存了账号密码 | 先用保存的凭据在后台静默重新登录一次；失败了，再在原地显示“登录已失效”和“登录”按钮 |
| 不打断人手上的事 | 发帖时点发送，页面立即关闭，在后台发送；失败后内容不在页面上了（PostFragment.java:517-518）。传图、发帖、清缓存都用不可取消的进度框，至少挡住 1–3 秒 | 留在编辑页，直到服务器确认成功再关闭；失败时留在原页，可以直接修改后重发。进度一律原地显示，不用阻塞式的进度框，也不人为拖延 |
| 难误碰 | 顶栏的返回箭头直接关闭编辑页并丢掉输入，系统返回键却会弹确认（PostFragment.java:387-389 和 736-748） | 所有返回途径（顶栏箭头、系统返回键、预测性返回手势）走同一条路径：自动保存草稿后返回 |
| 难误碰 | 开启“右划返回”后，整个屏幕宽度都响应右滑；首页任意位置右滑 32dp 就打开抽屉（SwipeBaseActivity.java:24-29、MainFrameActivity.java:482-501） | 取消自定义的全屏滑动手势，改用系统的预测性返回（只从屏幕边缘触发）；没有抽屉了 |
| 难误碰 | 看图时单击直接关闭，长按才显示工具栏；下拉关闭要先横向滑过一个阈值（ImageViewerLayout.java:56-74、231-289） | 按通行做法：单击显示或隐藏工具栏，双击放大或还原，下拉关闭（跟手，可以中途取消），长按弹出保存和分享 |
| 难误碰 | 点通知按钮一次，就把全部提醒的未读数清零；左滑删除搜索历史、字体、日志，没有撤销 | 提醒只在真正看过之后才算已读；删除操作统一用可撤销的 Snackbar |
| 按下去有回应 | 黑名单的“移除”按钮点了直接消失，没有进度；用户资料页切换内容时先变成白屏 | 按钮原地变成进度圈；切换内容时用 6.3 的“内容替换”处理 |
| 界面自己说明自己 | 退出登录藏在“长按头像”里，只靠一条 Toast 提示 | 在“我的 → 账号”里明确提供“退出登录”和“切换账号” |
| 同一件事处处一样 | 跳页面板里，“上一页、下一页”不收起面板，“首页、末页”会收起（ThreadDetailFragment.java:885-918） | 跳页的任何操作都会收起面板，并跳到目标位置 |
| 界面自己说明自己 | 错误提示直接显示异常类名或“错误代码 (403)”；空列表只有一片空白 | 错误提示统一成“发生了什么，加上怎么办”，技术细节放在可以展开的“详情”里；空状态显示一个图标、一句话，以及下一步可以做的操作 |

## 8. 文案
- 语气：简短、直接、口语化；不用感叹号；用全角中文标点。
- 术语表（唯一说法）：回复（不说“回帖”）；发新帖（不说“发表”或“发布”）；引用回复；收藏；关注；短消息（不说“私信”“信息”）；提醒（不说“信息提醒”“消息通知”）；只看楼主（只看主帖作者）；只看此人（只看某一楼的作者）；TA 的帖子（不说“搜索帖子”）；草稿；版块（不说“版面”）；分类（帖子的主题分类）；楼（第 N 楼）；加载失败（配“重试”）；暂无内容。
- 进行中的提示写清楚是什么动作：正在发送…、正在登录…，不写“请稍候…”“正在处理…”。
- 不把内部名词展示给用户：不出现 BBCode 标签名（如 `[attachimg]`）、异常类名、HTTP 状态码。
- 错误提示的格式：“[发生了什么]。[怎么办]”，例如“网络连接失败。下拉重试”“需要先登录才能回复”。
- 按钮写成动词：回复、发送、重试、登录、撤销。

## 9. 关键流程
- **首次启动**：直接显示论坛的帖子列表，未登录也可以浏览论坛允许游客看的内容。需要登录的操作（回复、短消息等），在原地显示登录入口。
- **Cloudflare 验证**：系统先在后台自动完成验证，用户看不到；只有需要人工操作时，才从底部升起一个验证面板，验证完成后自动收起，原来的请求自动继续。
- **登录**：一个页面完成（用户名、密码、安全提问）；登录后回到触发登录之前的页面和操作。
- **读帖**：打开帖子时回到上次读到的位置；底部工具条显示“第 N / M 页”，点它弹出跳页面板（可拖动的滑块，加上首页和末页）；在引用上点一下，跳到被引用的那一楼，并让那一楼的背景短暂高亮一下；返回时回到跳转之前的位置。
- **回复**：点底部工具条的回复，输入条升起，键盘同时出现，帖子内容随之上移，正在读的那一楼保持可见；发送成功后，新的楼层插入到末尾并滚动到它，输入条收起。

## 10. 验收条件
每条都有可检查的证据。M4 及以后，每张界面卡都要从这里挑出适用的条目，写进它的验收。

### 10.1 全局
- [ ] **截图矩阵**：每个页面的主要状态（有内容、空、出错、加载中）× 4 种宽度（411dp 手机、700dp 折叠屏竖向内屏、900dp 折叠屏横向内屏、1280dp 平板）× 深浅色，都有 Roborazzi 截图，并纳入基准对比。证据：CI 中 `verifyRoborazzi` 通过。
- [ ] **动效令牌唯一**：除了动效令牌文件，代码里不得直接出现 `tween(`、`spring(`、`durationMillis`。证据：一个扫描源码的单元测试；有例外时放进一个只能缩短的白名单。
- [ ] **减少动态效果**：在动画时长缩放为 0 的条件下运行 UI 测试，所有页面切换都在一帧之内完成，且没有残留的中间状态。证据：测试报告。
- [ ] **可打断**：对层级前进和返回、面板出现和消失、选中胶囊的移动，在动画进行到一半时再次触发相反的操作，逐帧检查位置连续：相邻两帧的位移不超过正常动画中单帧的最大位移。证据：Compose UI 测试（用 mainClock 控制时间）。
- [ ] **无布局跳动**：图片加载前后、刷新前后、展开引用前后，可见的第一楼与屏幕顶部的距离变化不超过 1dp（除了被展开的那一项本身）。证据：UI 测试。
- [ ] **性能**：长帖（300 楼以上，带图）滚动时，Macrobenchmark 的帧时间满足：P90 低于一帧的时间预算，卡顿帧不超过 1%。证据：CI 模拟器的基准报告；用户有真机时附真机数据。
- [ ] **术语统一**：字符串资源里不得出现第 8 节禁用的说法（回帖、发表、发布、只看该作者……）。证据：一个扫描字符串的单元测试。
- [ ] **错误提示**：用户可见的字符串里不得包含异常类名或 HTTP 状态码。证据：同一个扫描测试，加上对错误映射函数的单元测试。
- [ ] **无障碍**：触摸目标不小于 48dp；所有图标按钮都有内容描述；文字对比度不低于 4.5:1，包括毛玻璃降级之后。证据：Compose 无障碍检查（Robolectric 中开启 AccessibilityChecks）。

### 10.2 自适应
- [ ] 3 种宽度下，导航形态和单栏、双栏符合 4.1 和 4.2。证据：截图矩阵。
- [ ] 折叠和展开的连续性符合 4.3：选中的帖子、页码、楼层、偏移量、输入框内容都保持。证据：用改变窗口尺寸的测试模拟展开和折叠，再加 StateRestorationTester 模拟进程被回收后的恢复。
- [ ] 铰链把屏幕分开时（`isSeparating` 为真），两栏的分界对齐铰链；内屏展平时不避让折痕。证据：用模拟 FoldingFeature 的测试截图，两种状态各一张。
- [ ] 中等宽度的双栏：700dp 宽时显示双栏，导航是底部胶囊。证据：截图矩阵中 700dp 那一列。

### 10.3 毛玻璃
- [ ] API 31 及以上有真实的模糊；API 30、省电模式、降低透明度这三种情况都降级为不透明表面。证据：截图测试的 4 个变体。
- [ ] 内容延伸到导航下方滚动，列表最后一项完全可见。证据：滚动到底部时的截图测试。

## 11. 待用户确认
- 帖子详情里的“举报”功能其实没有发出任何网络请求，只是随机等待 1–3 秒后提示“感谢您的反馈”（ThreadDetailFragment.java:999-1046）。建议：如果论坛有举报接口，就实现真正的举报；如果没有，就删掉这个入口。删除现有功能需要用户同意。

## 12. 不做的事
- 不学 fluxdo 的这些部分：AI 功能、小应用、实时聊天、徽章和积分、可自定义的底栏、桌面多窗口、无限层叠的“胶片带”页面栈（帖子里最多进入一级，即用户资料）、可拖动调整两栏宽度。
- 不加装饰性的动效：不加视差、不加入场时的逐项级联动画、不在列表上做弹性滚动。
